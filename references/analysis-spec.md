# 元察分析规范（五块规范）

本文是元察（yotta-logwatch）的分析规范总纲，定义四类日志（auth / web / powershell / winevt）共用的
判型、字段提取、风险判定、分析流程与输出报告规范，供人工复核与调参。各类型规则细节见
references/auth-log-rules.md、web-log-rules.md、powershell-log-rules.md、windows-event-rules.md。

## 1. 判型规范

- **自动嗅探**：引擎按行特征判断类型，优先级 web → winevt → auth → powershell（Event 4104 / 4103
  脚本块记录仍走 powershell，避免与 winevt 抢判）。
- **强制指定**：`--type auth|web|powershell|winevt` 可跳过嗅探；混排文件可分文件指定。
- **判型依据**：每种类型有明确 marker 表（见各类型规则文档）；无法识别的行不产生事件、不参与检测。

## 2. 字段提取规范

判型后按类型提取规范字段（能提则提），统一事件结构：

| 字段 | 说明 | auth | web | powershell | winevt |
|---|---|---|---|---|---|
| time | 事件时间（ISO） | ✓ | ✓ | ✓ | ✓ |
| source | 来源 IP / 主机 | ✓ | ✓ | — | ✓ |
| user | 用户 / 账号 | ✓ | — | — | ✓ |
| event_id | 事件 ID | — | — | ✓（4104 等） | ✓ |
| provider | 提供方 | — | — | ✓ | ✓ |
| workstation | 工作站 | — | — | — | ✓ |
| action / outcome | 动作与结果 | ✓（failed/success） | ✓（方法/状态码） | — | ✓（failed/success） |
| message / 原始行 | 证据原文 | ✓ | ✓ | ✓ | ✓ |

## 3. 风险判定规范

- **严重度**：info / low / medium / high / critical（与 Sigma 社区 level 分级对齐）；
  `--min-severity` 过滤低价值噪音。
- **判定原则**：单条特征命中 → 按规则定级；聚合行为（爆破、撞库、404 洪峰）→ 按数量与时间窗升级；
  可解释性优先——每条命中带中文说明与复核建议，只做「可疑提示」，不做结论。
- **攻击链视角**：登录失败 / 成功（T1110 / T1078）、账户操作（T1136 / T1098）、日志清空（T1070.001）、
  进程 / 服务 / 计划任务（T1059 / T1543 / T1053）可跨类型交叉关联。

## 4. 分析流程 SOP

采集 → 判型 → 归一 → 时间线 → 异常命中外提 → 多日志关联 → 根因 / 影响 → 报告

1. **采集**：只读本地；EVTX 先导出文本；目录扫描只取日志特征文件。
2. **判型**：自动嗅探或 `--type`。
3. **归一**：提取规范字段，转为统一事件结构。
4. **时间线**：命中按时间排序。
5. **异常命中外提**：按严重度过滤，优先 critical / high。
6. **多日志关联**：同来源跨类型（如 auth 爆破 + web 扫描 + winevt 异常登录）人工关联。
7. **根因 / 影响**：结合业务上下文判断，只给复核建议。
8. **报告**：文本 / JSON / Markdown 三选一，见输出报告规范。

## 5. 输出报告规范

- **三格式**：文本（人类可读）、JSON（stdout 纯净，机器可读）、Markdown（存档 / 汇报）。
- **内容结构（引擎固定）**：报告头（工具 / 版本 / 生成时间 / 输入文件 / 扫描事件数 / 命中数）→
  命中详情（严重度 / 类型 / 时间 / 来源 / 用户 / EventID / 证据原文 / 中文说明）→ 汇总（严重度计数）。
- **证据链**：每条命中带原始行（evidence），保证可回溯复核。
- **外部报告模板（人工扩展）**：概述 / 时间线 / 命中明细 / 攻击链假设 / 根因 / 复核建议 / 证据链原文。
